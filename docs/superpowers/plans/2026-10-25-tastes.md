# Tastes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A global Tastes profile (genres, countries, actors, minimum rating, swipe verdicts) that filters and ranks every TMDB list in the app, with a rerunnable swipe wizard in Settings.

**Architecture:** Pure rules in `src/core/tastes_rules.js` (no imports, testable in node). A thin store in `src/core/tastes.js` reads and writes the `tastes` key through `Storage` and exposes the rules to the app. `src/core/api/api.js` wraps result callbacks with `Tastes.apply`. `personal_rows.js` builds discover URLs from `discoverParams`. The wizard lives in `src/interaction/tastes/` and is reached from a Settings component.

**Tech Stack:** Vanilla JS modules (Rollup/Gulp build), jQuery-style DOM used across `src/interaction`, vitest (`spec/**/*.spec.js`, node environment).

**Spec:** [docs/superpowers/specs/2026-10-25-tastes-design.md](../specs/2026-10-25-tastes-design.md)

**Deviation from spec:** the spec puts all logic in `src/core/tastes.js`. The pure rules are split into `src/core/tastes_rules.js` so vitest can import them without loading `Storage`. `src/core/tastes.js` keeps the storage and app-facing functions the spec lists.

## Global Constraints

- Storage key: `tastes`. Shape exactly as the spec's data model.
- Verdict keys: `'movie:' + id` or `'tv:' + id`. Verdicts: `like`, `dislike`, `skip`. `skip` hides nothing and is no signal.
- `min_rating` range `0..10`; `0` means off.
- Discover floors for the wizard deck: `vote_count.gte=300`, `vote_average.gte=7`, sorted by popularity.
- Every new string exists in both `src/lang/en.js` and `src/lang/uk.js`, keys prefixed `tastes_`.
- The library (`favorite()` in `src/core/api/api.js`) and the title detail page (`full()`) are not filtered.
- Tests live in `spec/` and match `*.spec.js`.

## Review Focus

1. Storage holds a corrupt or missing `tastes` value (null, string, array). Expected: the app runs with an empty profile and nothing is filtered.
2. An empty profile. Expected: every API result passes through unchanged, same order, same objects.
3. A card with `vote_average` missing or null while `min_rating > 0`. Expected: it is hidden (unrated titles don't pass a rating rule).
4. A `discover` request fails. Expected: the row falls back to the existing unfiltered request, and no row is lost.
5. `search()` returns no movie or no tv item. Expected: no crash, and the missing side stays `undefined`.

Each line above is pinned by a test in the task that owns the code (Tasks 1, 2, 3, 4).

```js
import {expect, test} from 'vitest'
import R from '../src/core/tastes_rules.js'

const empty = R.defaults()

test('defaults and normalize survive bad input', () => {
    expect(R.normalize(null)).toEqual(R.defaults())
    expect(R.normalize('x')).toEqual(R.defaults())
    expect(R.normalize([])).toEqual(R.defaults())
})

test('empty profile passes every card and keeps order', () => {
    const list = [{id: 1, vote_average: 2}, {id: 2}]
    expect(R.apply(empty, list)).toEqual(list)
})

test('apply on non-array returns []', () => {
    expect(R.apply(empty, undefined)).toEqual([])
})

test('dislike hides, skip does not', () => {
    const p = {...empty, verdicts: {'movie:1': {verdict: 'dislike'}, 'movie:2': {verdict: 'skip'}}}
    expect(R.match(p, {id: 1, title: 'a'})).toBe(false)
    expect(R.match(p, {id: 2, title: 'b'})).toBe(true)
})

test('min_rating hides unrated and low titles', () => {
    const p = {...empty, min_rating: 7}
    expect(R.match(p, {id: 1, vote_average: 6.9})).toBe(false)
    expect(R.match(p, {id: 2, vote_average: null})).toBe(false)
    expect(R.match(p, {id: 3, vote_average: 7})).toBe(true)
})

test('genres and countries use any-match', () => {
    const p = {...empty, genres: [28, 35]}
    expect(R.match(p, {id: 1, genres: [{id: 35}]})).toBe(true)
    expect(R.match(p, {id: 2, genres: [{id: 18}]})).toBe(false)
})

test('score ranks likes and matches higher, never hides', () => {
    const p = {...empty, genres: [28], verdicts: {'movie:1': {verdict: 'like'}}}
    expect(R.score(p, {id: 1, genres: [{id: 28}]})).toBeGreaterThan(R.score(p, {id: 2, genres: [{id: 18}]}))
})

test('discoverParams omits unset fields', () => {
    expect(R.discoverParams(empty, 'movie')).toEqual({})
    expect(R.discoverParams({...empty, genres: [28, 35], min_rating: 7}, 'movie'))
        .toEqual({with_genres: '28,35', 'vote_average.gte': 7})
})
```

- [ ] **Step 3: Implement the store**

`get()` returns `R.normalize(Storage.get('tastes', null))`. `set(patch)` merges `patch` into `get()`, sets `updated = Date.now()`, and writes with `Storage.set('tastes', …)`. `verdict(card, value)` writes or removes `verdicts[R.verdictKey(card)]`, storing `title: card.title || card.name`. `reset()` writes `R.defaults()`. `apply`, `discoverParams`, `match` delegate to the rules using `get()`. Wrap each `Storage` call in try/catch and on failure leave the in-memory value unchanged; the notice is shown by the wizard (Task 5), not here.
